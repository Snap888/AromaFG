## Source findings

1. **Timing propagation:** fixed in current branch and covered by a conditional device-smoke regression assertion when timestamp collection is available. Android physical re-run remains required.
2. **Driver diagnostics:** smoke now attempts to print driver name/info/conformance through `VkPhysicalDeviceDriverProperties` when Vulkan 1.2 properties2 is available. The prior report did not capture those fields.
3. **Host integration boundary:** current smoke creates and owns its test Vulkan device/queue, then passes the context and command buffer to AromaFG. It verifies the API boundary in a controlled host test, not integration with a third-party renderer, Winlator, DXVK or a game.
4. **Algorithm maturity:** the current graph is a synthetic optical-flow/frame synthesis smoke. It does not establish perceptual quality against high-FPS ground truth, real-game robustness, or 1080p/1440p performance. The 320×180 timings are not scalable performance evidence.
5. **Validation:** the physical run had validation layers disabled. Linux lavapipe synchronization validation is useful software evidence but is not a substitute for validation on Adreno/Turnip.
